# 디자인 시스템 — Vibe 참고, 라이트 테마

## 목적

화면을 **미니멀**하게 유지한다. 목록은 핵심만, 나머지는 클릭해서 본다.
monday.com 의 Vibe UI Kit 을 참고했다 — 라이트 서피스, 8px 라운드, 파란 프라이머리, 파스텔 칩.

> Figma 원본 파일은 접근하지 못했다(로그인 필요). 아래 토큰은 Vibe 의 공개된 값과 특징을 옮긴 것이라
> 실제 킷과 다를 수 있다. 색을 맞출 일이 생기면 `main.css` 의 `:root` 한 곳만 고친다.

## 레이아웃 규칙

1. **탑바 3분할** — 왼쪽 브랜드 / 가운데 세그먼트(`채용공고`·`모집 직무`·`기업`, 홈은 채용공고) / 오른쪽 관리자 버튼 + 아바타.
   관리자는 성격이 달라 세그먼트에 넣지 않는다. 관리자 계정에게만 보인다.
2. **한 페이지 = 얇은 헤더 + 카드 그리드.** 히어로 문구·설명 단락을 두지 않는다.
   헤더에는 제목, 개수, 주 동작 버튼만.
3. **목록 카드는 핵심만.**
   - 공고: D-day · 모집 부문 · 회사 · 내 상태 · 직무 수
   - 직무: 직무명 · 회사 · D-day
   - 기업: 이름 · 형태 · 업종 2개(+n)
   그 외 필드는 카드에 올리지 않는다. 카드가 길어지면 목록이 아니라 상세가 된다.
4. **상세와 수정은 같은 드로어**(`Drawer.vue`, 오른쪽에서 열림)에서 한다.
   카드를 누르면 `보기`, `수정` 을 누르면 같은 자리에서 폼으로 바뀐다. 별도 모달을 띄우지 않는다.
   **동작 버튼(수정·삭제·보관·취소·저장)은 드로어 헤더 바로 아래 한 줄**(`#actions` 슬롯)에 둔다. 하단 푸터 없음.
5. **드로어 안의 종속 데이터는 더블클릭하면 그 데이터의 화면이 열린다.**
   기업 → 채용정보 행 → 공고, 공고 → 모집 직무 행 → 직무. 행은 `<button class="mini-row">` 이고
   `@dblclick` 과 `@keydown.enter` 를 함께 받는다(키보드로도 열려야 한다).
   화면을 넘길 때는 `?focus=<id>` 를 붙인다 — 링크로 공유·북마크된다. 라우팅은 `App.vue` 만 한다.
   **역방향(부모로 가기)은 버튼이다.** 부모는 하나뿐이라 행이 아니라 이름 옆 `.link-button` 을 한 번 눌러 간다:
   공고 → 고용회사, 직무 → 소속 공고.
6. 파괴적 확인만 가운데 모달(`ConfirmDialog`).

## 컴포넌트

| 이름 | 파일 | 비고 |
|---|---|---|
| 세그먼트 | `App.vue` `.segmented` | 라우트 전환 전용 |
| 카드 그리드 | `.card-grid` + `.card` | 기업·공고 공용 |
| 칩 | `.chip`(중립) `.chip[data-tone]` | 상태·업종·형태 |
| D-day 배지 | `.dday[data-tone]` | tone 은 `types/posting.ts` 의 `ddayTone()` |
| 드로어 | `Drawer.vue` | props `title`, `subtitle`; `#actions`(헤더 아래) `#default` 슬롯 |
| 종속 행 | `.mini-row` (button) | 더블클릭·Enter 로 그 데이터의 화면을 연다. `user-select: none` |
| 절차 체인 | `.step-chain` `.step-node[data-result]` | `PostingDetail` — 노드 클릭으로 결과 순환 |
| 가로 스트립 | `.strip` | 직무 드로어의 참고 정보 카드 |
| 폼 | `CompanyForm` `PostingForm` | **바깥 껍데기 없음** — 드로어가 감싼다 |
| 확인 | `ConfirmDialog.vue` | 유일한 가운데 모달 |

## 실행·검증

```bash
cd frontend && npm run type-check && npm test
docker compose up -d --build && bash scripts/smoke.sh
```

화면은 로그인이 필요해 스모크로 확인할 수 없다. 브라우저에서:
1. 탑바 세그먼트에 `기업`·`채용공고` 둘만 있고 관리자는 따로 떨어져 있는가
2. 카드에 핵심 필드만 있는가
3. 카드 클릭 → 드로어 상세 → `수정` → 같은 드로어에서 저장되는가

## 함정

- **폼 컴포넌트는 스스로 모달을 만들지 않는다.** 드로어 안에 들어가는 것이 전제다. 껍데기를 다시 붙이면 드로어 안에 모달이 겹친다.
- 카드에 필드를 추가하고 싶어지면 상세에 넣는다. 규칙 3이 이 화면의 존재 이유다.
- **`.mini-row` 는 `<div>` 가 아니라 `<button>` 이다.** `<div>` 로 되돌리면 더블클릭이 글자만 선택하고 키보드로는 아예 열 수 없다.
- 라이트 테마 하나뿐이다. 다크 토글은 없다 — 요구된 적이 없다.
